Teach 11 modelsfrom the examples

Every model taught in the course learns from the same 3,44,246 prepared rows. None of them is a formula we wrote: each is a ready-made class in scikit-learn, a free machine learning library. We choose a few settings, hand it the rows and their answers, and the library does the learning.

Words used on this page

Library
Ready-made code someone else wrote and shared, which we install and use, like an npm package. We don't write the algorithms ourselves.
scikit-learn (sklearn)
The free, open-source Python library that contains all 11 algorithms used here. It is the standard ML library taught in the course.
Class
A ready-made blueprint in the library, like RandomForestClassifier. We create one with our settings, then use it.
.fit(rows, answers)
The one command that makes a model learn: it hands the training rows and their answers to the library, which does the rest.
Model
The result of training: a function that takes a row's 45 numbers and gives back a chance of attack.
Weight
A number the model learns for each column, saying how much that column counts and in which direction.
Decision tree
A flowchart of yes/no questions about the columns, ending in end points (leaves) that say normal or attack.
Cut-off
The number inside a question, like the 113 in 'rst_count > 113?'. The library picks it.
Random resample
A new pile of rows drawn at random from the training rows, where a row can be picked more than once (also called a bootstrap sample).
Vote / average
Combining many models' answers into one: the share of trees that say 'attack', or the average of their chances.
S-curve (sigmoid)
A fixed formula that turns any score into a chance between 0% and 100%: score 0 → 50%.
Chance of attack
The model's answer, from 0% to 100%. At 50% or more we call it an attack (that 50% is the alarm threshold).

What 'training' means

The same four steps for every one of the 11 models.

  1. 1The prepared rows

    3,44,246 rows × 45 numbers, plus each row's answer (0 or 1)

  2. 2model.fit(rows, answers)

    the library adjusts the model's inner numbers (its parameters) until its guesses match the answers

  3. 3A trained model

    its learned numbers: weights, tree questions, cut-offs…

  4. 4model.predict_proba(new row)

    'predict probability': a chance of attack for a row it has never seen, e.g. 93%

from sklearn.ensemble import RandomForestClassifier   # 1. load a ready-made model from the library

model = RandomForestClassifier(n_estimators=200)     # 2. create it with our settings (200 trees)
model.fit(X_train, y_train)                          # 3. learn: X_train = the 344,246 rows of 45 numbers,
                                                     #           y_train = their answers (0 or 1)
model.predict_proba(X_test)                          # 4. chance of attack for each exam row it never saw

Key words

Supervised learning
Learning from examples that come with the right answer.In our project10 of the 11 models learn from rows tagged normal (0) or attack (1). K-Means is the exception: it never sees an answer.
Training (.fit)
Running the learning method on the examples so it works out its inner numbers.In our projectEvery model calls .fit() on the same 3,44,246 rows; it took from 0.4 seconds (KNN) to 235 seconds (AdaBoost).
Parameters vs settings
Parameters are what the model learns by itself; settings (hyperparameters) are what we choose beforehand.In our projectRandom forest: we set '200 trees' (a setting); the questions inside each tree are learned (parameters).
Overfitting
Memorising the training examples instead of learning the pattern, so the model looks great on them and worse on new rows.In our projectOne decision tree overfits easily; random forest, bagging and early stopping exist largely to prevent it. The locked exam rows catch it.
Ensemble
A model made of many smaller models that vote or add up.In our projectRandom forest (200 trees), bagging (100), AdaBoost (200 stumps) and gradient boosting (300 trees). Three of them took the top three places in step 5.

How it did on the exam: step 5

The problem it solves

One decision tree overfits (memorises its training rows) and is unstable (see the decision tree above). Many trees that each make different mistakes, averaged, cancel most of those mistakes out, like asking 200 analysts instead of one.

How it decides

  1. Tree 1 gets its own random resample of the 344,246 training rows: rows are drawn at random one by one, and a drawn row can be drawn again, so some appear twice and about a third are left out. This is called bootstrapping.
  2. The tree is grown with the same method as the single decision tree, with one twist: at every question it may only look at about 6 randomly picked columns out of 45, so the trees can't all lean on the same few clues.
  3. Repeat for all 200 trees, each with its own random resample and random columns. For a new row, each tree gives its chance and the forest averages the 200 (its 'vote').

Where do the 200 trees come from? Do we build them?

No. scikit-learn already contains the code to build one decision tree (the same code as model 3 above). RandomForestClassifier simply runs that tree-building code 200 times in a loop, handing each run a different random resample of the rows. We wrote neither the tree logic nor the loop: we only set the number 200. When we call .fit(), the library builds all 200, and it took 94 seconds.

Why are the 200 trees different if the method is the same?

Because each one sees different rows (its own random resample) and, at every question, a different random handful of columns. Same recipe, different ingredients, so different trees.

Where the code comes from

A ready-made class (a blueprint of code someone already wrote) from scikit-learn, the free machine learning library: we import it (load it into our program), choose the settings, and call .fit() (the "now learn" command). The learning itself is done by the library.

from sklearn.ensemble import RandomForestClassifier
model = RandomForestClassifier(n_estimators=200, n_jobs=-1)
n_estimators = 200how many trees to grow. This is the only real choice we made
n_jobs = -1use every processor core (each core is one worker inside the computer's chip), so several trees grow at the same time

What training works out by itself (its parameters): 200 complete decision trees, every question and cut-off chosen by the library from the data.

Good at: Much more accurate and stable than one tree; tied for the best catch rate here.

Weak at: Big: 200 full trees saved to a 106 MB file, too heavy to send to a browser.

What we learnedNo single tree is sure of anything; each adds a nudge worth a tenth of its vote. Together, 300 of them push a row from the starting 73.7% (the share of attacks in training) to a confident answer. The quiet spoofing row shows the weak spot: the trees pull it down from 73.7% to below the 50% alarm line, so it gets through.
