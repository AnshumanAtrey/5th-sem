Get the data readyfor learning

Models only understand clean numbers on a fair scale, with the answers kept apart. These five steps get the data there, in the order we ran them.

1. Take a fair sample

46.7 million rows is too many to train 11 models on, and step 1 showed how uneven they are. So we keep a smaller part, chosen so the rare attacks don't get lost.

4,66,86,579 rows in total

The rule: every attack type keeps up to about 12,000 rows, picked at random from all 169 files; a type with fewer keeps all of them. Normal traffic keeps about 120,000, so there are plenty of normal examples too.

Key words

Class imbalance
When some answers have far more examples than others.In our projectDDoS floods are 73% of all 46.7 million rows; web attacks are only 0.05%.
Biased (toward the majority class)
A model that learns mostly from one big group and leans toward always answering it, neglecting the small groups.In our projectTrained on all the rows, the model would learn floods very well and mostly ignore web attacks and brute force. So we kept every rare-attack row and only cut the repeated floods.

What we learned4,66,86,579 rows became 4,58,995 (about 1%), and every rare attack is still there: web attacks went from 0.05% of the data to 5.4%.

2. Check for junk

Before learning anything, every row and column is checked for problems.

  • Duplicate rows0 found

    The same row twice could land in both the learning set and the exam, so the exam would partly test memory.

  • Same numbers, different answers0 found

    Two identical rows with different labels can't both be right; no model could learn them.

  • Empty cells0 found

    Models can't do maths on a blank.

  • Infinite values0 found

    A division by zero somewhere upstream would show up as infinity.

  • Negative values0 found

    No count, size or duration can be below zero.

  • Columns that never changeSMTP

    Always the same value, so it tells the model nothing. Kept: after scaling it becomes all zeros and can't affect anything.

  • Columns that copy anotherRate = Srate, IPv = LLC

    Kept as well, so the app accepts a standard CICIoT2023 row as-is.

What we learnedThe data is clean: no duplicates, no blanks, no impossible values, so all 4,58,995 rows stay. Only one column (SMTP) is useless and two pairs are copies, and none of them can do harm.

3. Turn the answers into numbers

Models do maths, so the text answer (like "DDoS-ICMP_Flood") has to become a number. We make two answer columns: the attack family, for the 'which attack?' model, and a single 0 or 1 for the main 'is it an attack?' detector.

What we learned34 text labels became 8 families and one yes/no column: 0 for normal traffic, 1 for any attack. The 45 number columns need no change here: they are already numbers (the protocol ones are already 0 or 1).

4. Lock away a final exam

A model can memorise the rows it learns from. The only fair test is on rows it has never seen. So before any learning, a quarter of the rows are put aside, and no model looks at them until grading.

What we learnedEvery family, and inside it every one of the 34 labels, is split the same 75 / 25 way (a stratified split), so even the rarest attacks get fairly graded. A model that always says "attack" would already score 73.7% on this exam, which is why step 5 looks past plain accuracy.

5. Put every number on one scale

Speed goes up to millions; 'uses TCP' is just 0 or 1. Many models would let the huge numbers drown out the small ones. So every number goes through the same four steps. Pick a column and a row, or type your own value, and follow it.
