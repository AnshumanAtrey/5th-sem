Every model startswith examples

A computer can't recognise an attack it has never seen. So before anything else, we need lots of real network traffic, each piece tagged with the right answer: normal, or which attack. This tab shows where those examples come from and what one of them looks like.

Who made the data

We didn't record any traffic ourselves. Researchers at the Canadian Institute for Cybersecurity (University of New Brunswick, Canada) built a smart home in their lab, attacked it on purpose, recorded everything and published it in 2023 so anyone can study it. It's called CICIoT2023 (their paper).

From a recording to a table

How a smart home under attack became rows of numbers.

  1. 1

    A smart home in a lab

    105 real devices: cameras, smart speakers, plugs, bulbs, sensors, a TV, a robot vacuum.

  2. 2

    Attacked on purpose

    7 Raspberry Pi mini computers attack them with real tools (hping3, nmap, ettercap, the real Mirai code). The rest of the time, nothing attacks: that's the normal traffic.

  3. 3

    Every packet recorded

    A network tap copies everything on the wire, and Wireshark saves it as .pcap recordings.

  4. 4

    Boiled down to numbers

    Every 10 or 100 packets in a row are summarised into 46 numbers: speed, packet sizes, TCP flags, protocol.

  5. 5

    One big table

    Each summary becomes one row of a CSV file (a plain-text spreadsheet), tagged with what was really happening. 46.7 million rows in 169 files.

The answers the model can give

Every row is tagged with one of 34 labels: normal traffic, or one of 33 attacks. The attacks come in 7 families. Open one to see what it is.

What it is
Everyday traffic with no attack going on: a camera streaming video, a smart plug checking in with its cloud, a speaker fetching music. Its label in the data is BenignTraffic (benign means harmless).
How the lab made it
Recorded while the devices were simply being used, with no attacker running.
How it shows in the numbers
A wide mix of packet sizes, and connections that last a while (half last over 25 seconds).
Its label in the data
  • BenignTraffic10,98,195

The data is very uneven

This is called class imbalance. Floods (DDoS) are 73% of all rows. Web attacks are 0.05%, so small their bar barely shows. Left like this, a model would hardly ever see a web attack and would never learn it. Step 3 shows how we fixed that.

How the files got into our code

Nothing here is hand-made or typed in: the table we use is exactly what the researchers published.

  1. Kaggle, a free data-science website, keeps a copy of all 169 files.
  2. We opened a free Kaggle notebook: a computer in the cloud that runs Python, with the files attached.
  3. We read them with pandas, a free ready-made Python library for tables. Think of it as an npm package for spreadsheets: we install it and call it, we don't write it.
import pandas as pd            # load the library

table = pd.read_csv("part-00000.csv")
table.shape                    # (238687, 47)
# → this one file: 238,687 rows, 47 columns
#   (46 numbers + the answer)
